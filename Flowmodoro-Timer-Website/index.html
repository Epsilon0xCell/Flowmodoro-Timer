The clock is the page

Focus as long as you flow. The break takes care of itself.

I am Epsilon0xCell, and I built Flowmodoro-Timer as a timer with no target. On this page I replaced my old drawn ring with a working clock that runs the same rule as the app, and everything below it is the notebook that explains that rule.

The clock room

This is a page version of the same rule the app runs. It is not a recording and it is not linked to the app. Press Start focus and it counts up. Press Take break and it banks a break from your focus time and counts that break down. The session log under it works the way the app log works, newest entry first.

If the script does not run, the rule still reads plainly here: focus counts up from 00:00 with no set target, and when focus stops, the break is the focus time divided by 5, floored to whole seconds. Twenty five minutes of focus banks 05:00 of break. Fifty minutes banks 10:00. Thirty seconds banks 6 seconds. Under 5 seconds of focus banks no break at all.

    The rule, worked out

    I built this because a set target kept ringing in the middle of a thought. Flowmodoro counts up instead. I stop when the flow ends, and one constant in app.js decides what I earned. That constant is named RATIO, it holds 5, and my break is my focus time divided by it, with the fraction cut off.

    25:00of focus, stopped when the flow ends
    1 / 5the RATIO constant in app.js, the one number that sets every break
    05:00of break, counted down, then back to Ready

    The break is not a running balance. I recompute it each time a focus block ends. If I end a break early, I only get credit for the part I used. Reset throws the current phase away on purpose, and focus time before a Reset never reaches the totals.

    The constant, from app.js line 6

    const RATIO = 5;             // I earn 1 second of break for every 5 seconds of focus. If I change this one number, every break length in the app changes with it.

    Stopping focus, from app.js lines 115 to 123

        breakSeconds = Math.floor(focusSec / RATIO);
    log(`Focus: ${fmt(focusSec)} -> earned break: ${fmt(breakSeconds)}`);
    totals();
    // I floor the division above, so under 5 seconds of focus earns 0.
    // I treat that as no break at all instead of starting a 0 second break that ends at once.
    if (breakSeconds < 1) {
      toIdle("Under 5 seconds of focus - no break banked.");
      return;
    }

    Three states hold the whole thing together. The mode variable in app.js is always idle, focus, or break, and a helper named toIdle sends every path back to Ready: break finished, break ended early, focus too short to bank a break, and Reset. I kept the same shape on this page, including the same status lines, so the page clock and the app clock disagree about nothing that matters.

    Time comes from the wall clock, not from counting ticks. The render step subtracts startedAt from Date.now() every time it draws, on a 250 millisecond interval. A background tab can throttle that interval and make the readout less smooth, but it cannot change Date.now(), so the time stays right.

    What the app adds

    The clock on this page is the timing rule on its own. The app itself, in index.html and app.js at the root of the repository, adds one more room: ambience. I paste a YouTube study space link into a box and the app loads it as an embedded player under the timer, so the room I am working in has a sound and a view to go with the counting.

    I skipped that player here on purpose, and I am saying so plainly instead of letting anyone wonder where it went. This page is about the timing rule. The embed is the app room, not this page room. If you want the ambience, run the app: it is one page of its own, index.html with style.css and app.js at 165 lines, and the player loads there after a pasted link passes a strict check for a v= link, a youtu.be link, an embed link, or a bare 11 character video ID as the whole input.

    • The app clock is text. style.css gives it tabular numbers, so a 1 takes the same width as an 8 and the readout does not jitter as it counts. I kept tabular numbers on this page for the same reason, only much larger.
    • The app log is plain text. Each entry is set with textContent, so log text is never read as markup. My page log does the same.
    • The app totals stay in seconds. They round to minutes only when shown, so short sessions do not each round their seconds away. My page totals follow that too.

    Run it

    To run the app itself, open index.html at the root of the repository in a browser. That is the whole install. Or serve the folder and open the local address:

    # from the repo root
python3 -m http.server
# then open http://localhost:8000 in a browser

    To read this page on its own, open Flowmodoro-Timer-Website/index.html in a browser, or serve that folder the same way and open http://localhost:8000.

    One honest note

    The session log and the totals on this page, and in the app, live only in the browser tab. Closing the tab loses them. I did not add storage, accounts, or sync, because I use this for one sitting at a time and that is the job it was built for. Timing is wall clock based, which is a choice I made in app.js and kept here: a throttled background tab loses smoothness, not accuracy.
